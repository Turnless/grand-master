# Contributing

Thanks for helping. This project is meant to be **forked and reshaped**. Change it however your workflow needs, and share improvements back if you like.

## Ideas that would help
- **New categories**, e.g. testing, API routes, database queries, accessibility, i18n
- **Example grand-masters** for other stacks (Vue, SvelteKit, Express, Django, Flutter, ...) in `examples/`
- **Better detection** in `master-learn`: smarter ways to spot patterns in a given framework
- **Bug reports**: the AI misread a pattern, promoted a bad rule, or skipped a step

## How to contribute
1. Fork the repo and create a branch.
2. Make your change. Skills are plain Markdown in `skills/<name>/SKILL.md`.
3. **Test it on a real project.** Run the skill you changed and check that the output makes sense.
4. Open a pull request saying what you changed, why, and what you tested it on.

## Guidelines
- Keep every step **readable by a vibe coder**. Someone who doesn't read code should still understand what the skill will do.
- Keep the grand-master template **short**. It loads every session.
- One idea per pull request.
